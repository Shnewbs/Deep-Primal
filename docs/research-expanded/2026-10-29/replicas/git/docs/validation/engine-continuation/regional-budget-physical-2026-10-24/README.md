# R48: physical chunk churn and promotion of regional discharge-rate fix

Source parent e5bfb8ff2c2ee865d94650e6ac57bbc189942cf0. This validates the unchanged
R46 candidate already built/tested in R47, and promotes its one HydrologyRuntime
file plus a private PhysicalRegionalChecks regression fixture. Reconstructed
RegionWork starts with its32-unit allowance exhausted; only a new aquifer step
resets it. No geography, quantity, chemistry, shader or saved-state-format change.

## Accepted physical server test

The fixture chooses two bounded-search non-ocean sites and prepares measured outlets
in two separate regions. Each delivers32 units through the actual loaded-column
visit path. It warms unrelated region caches through the production region helper,
loads/forces32 auxiliary chunks, releases their tickets **and the outlet tickets**,
then services the real server chunk manager until FULL lookups return null and
the active regional cache entry is gone. No cache maps or event bus are mutated.

Two cycles verify64 auxiliary physical eviction checks,32 auxiliary reloads with
different LevelChunk identities, four outlet reloads with different identities,
and64 real auxiliary ChunkEvent.Unload callbacks. Saved outlet water survives each
reload. Both active regions remain at32 units in the same aquifer interval. After
an explicit20-tick saved-game-clock advance, each delivers another32, bringing its
cumulative fixture output to64. Exact water, salt and sediment are conserved across
groundwater, snow, ocean, atmosphere and measured fixture cells after each cycle
and the following interval.

Chunk-manager service loops deliberately leave the level clock unchanged during
eviction; the next interval is explicitly advanced through ServerLevelData. These
are physical server evictions/reloads with controlled scheduling, not a claim of
independent60Hz simulation, real-time throughput or arbitrary natural-world churn.
This closes the scoped R46/R47 physical reload/rate-cap gate; larger-region,
weather/season, long-duration memory/latency and broader editable-world work remain.

The accepted packaged server run also passes the existing hydrology suite: shared
aquifer outlets, blockage/head limits, infiltration, bucket chemistry/advection,
accounted sea stage, finite inland water, weather debit, codec, once-only seeding
and no forced unloaded destination. A separate process reopens the disposable world
and verifies saved V4, groundwater, dynamic wet age, composition and player edits.
Both have explicit success files, clean requested stop/all-dimensions saves and no
crash reports.

## Build, package and self-audit

A fresh forced31-task full build passes core water accounting, R44 retirement,
V4/legacy terrain, full watershed, cache and module gates. Seven archive CRCs and
475 compiled product class identities pass; private validation remains excluded.
Native class origins identify the packaged root and standalone core. Relocation
changed ZIP container metadata in the standalone core (raw bytes are not equal),
but every core member matches the embedded module. Recursive leaf hashes also
prove every native-tested root/module member equals the freshly rebuilt bundle.
No whole-container equivalence is claimed where timestamps/ZIP metadata differ.

Three rejected private-fixture attempts produced actual game crash reports despite
Gradle exit zero. They are excluded and retained with source and raw logs:

- Fixed coordinates landed in an ocean region, where spring visits intentionally
  return without emitting; corrected bounded non-ocean site selection.
- A guessed pruning threshold ignored neighboring chunks loaded by forced tickets;
  replaced it with observed FULL eviction/cache clearing.
- The attempt retaining forced outlet tickets did not establish the combined
  eviction/cache-clear gate within its bound. The accepted fixture also releases
  outlet tickets and proves different outlet chunk identities after reload.

Runtime code did not change during these fixture corrections. The accepted results
are not inferred from Gradle exit status. No rejected attempt is called a passing
build/native session. Logs retain raw SHA256 in each result; compressed bytes are
lossless. R46 source-extracted baseline/control evidence and R47 event-only evidence
remain historical and are not relabeled as physical chunk tests.

The promoted source is HydrologyRuntime.java; PhysicalRegionalChecks.java is private
validation source. The Git parent plus source-manifest.json, these overlays and the
recorded JDK25/JDK21/Gradle9.2.1 commands reconstruct the build. Local runner/sealer
paths refer to the retained validation workspace. No owner installer was released;
the previously supplied Alpha26 JAR does not include this promotion. No graphics
client, Vulkan-driver, Windows, ownerGPU/FPS or performance acceptance follows.
Continue the current terrain/cave/material and bounded Vulkan publication priorities.
