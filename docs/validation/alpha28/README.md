# Alpha.28 compact evidence

Read ../../VALIDATION-0.0.1-alpha.28.md and ../../TERRAIN-V7.md for scope, failures and limits. `results.json` contains accepted process/fixture outcomes and matched stair inputs. `artifact-*.json` records independent core and packaged class identities. `platform-payload.json` compares Linux/Windows common entries with only platform archive paths normalized. Seed CSVs are fixed-ensemble measurements; widths are plan diameters. `legacy-digests.json` pins the byte-identical 5,202-point legacy output. `changed-source-manifest.json` pins final changed source, including private fixtures.

The owner validation ZIP retains raw console logs, screenshots, input hashes, original legacy CSVs and rejected attempts. Raw captures are evidence, not a performance claim. Native game log timestamps use the launch environment's local clock; report dates and foreground lease use UTC.

## Reproduction

On a normal Java25/Gradle setup run `./gradlew build` and platform bundles with `-PvulkanPlatform=linux` or `windows`. Private fixtures compile with `:visualValidationClasses`. Launch only `:runClient` or `:runServer` with `-PvisualValidation -PpackagedValidation -PvalidationJar=<absolute selected jar>` and a disposable run directory. Actual accepted assertions and scene commands are in `src/visualValidation`.

The `runners` directory retains exact audit orchestration. To reproduce the isolated host workflow, copy its files into a task directory with `project/` containing this source, `toolchain/` containing the pinned JDK25/JDK21/Gradle/cache/private graphics layout, `evidence/`, and `recovery/` with the released alpha.27 control. Use the repository's checksum-pinned tool restoration workflow; these runners do not download credentials or embed dependencies. `fresh-compile.gradle` prevents stale incremental core output. `verify_artifact.py` performs independent core compilation and every project class comparison; `audit_platforms.py` compares the resulting packages.

`native_audit.py baseline`, `initial`, `reopen`, `legacy-reopen`, `deep-initial`, `deep-reopen` run in that order and retain separate records. Initial modes require absent saves; reopen modes require their completed initial record. `client_audit.py create`, `baseline-bed`, `candidate-bed`, `scenes`, `gl-bed` use selected packaged bytes, disposable saved worlds and explicit backend checks. The GL mode tests smooth fallback; Vulkan modes include shutdown/resource assertions. The native-initial scene record supplies coordinates. Existing evidence directories must be preserved or a new task directory used; they are not overwritten. Do not run competing Gradle/native producers against the same outputs.

`client_audit.py` captures frames after a controlled wait. Inspect the actual images and pass records; elapsed time, an exit code or shader compilation alone is not visual acceptance. Frozen stair fixtures isolate meshing with matching volume; ordinary scene captures tick normally but are not hydrology endurance tests. No runtime source/refill policy is altered by the fixture.
