## Production work

`V8OutletLedgerStore` is a new, **explicit-call-only**, single-writer durable Java filesystem adapter for the existing immutable `V8ConservedOutletLedger`. An owner explicitly calls `create` for a new account store or `open` for an existing store; missing/corrupted existing checkpoints are never silently treated as a new world. The API provides a **generation compare-and-swap** `transact(expectedGeneration, transfers)`. Failed/stale concurrent proposals cannot both commit. Each canonical binary image contains **water, salt, sediment, capacity, receiver graph and replay receipts** in the same frame, deterministically sorted with a bounded count and SHA-256 checksum. A commit writes a sibling pending frame, forces it, replaces the authoritative file atomically and forces parent-directory metadata before publishing the new in-memory generation. A failed I/O/verification path poisons the writer until it is closed and reopened, because the rename may have happened before acknowledgement. File locks reject a simultaneous second participating writer. An exact last-receipt replay advances neither generation nor physical quantities.

This does **not** bind the store to Minecraft SavedData, native fluid cells, world lifecycle, actual lake/ocean authority, environmental budgets or a registered V8 generator. It does not coordinate changes to those systems with the store, modify player edits, rewrite saved geography, or automatically migrate old V8 snapshots. It is **not** proof of process-kill/power-loss durability on every filesystem; Linux directory-force/atomic-rename semantics were used in scoped tests only, and Windows/network filesystem behavior remains an owner-side gate. A complete native transaction still must couple finite-cell mutations with this world-owned authority, including loaded/unloaded and restart reconciliation.
