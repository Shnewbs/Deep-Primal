## Production correction

`V8OutletLedgerStore` adds an opt-in, immutable **V2 bound checkpoint** and two explicit API entry points: `createBound(file, snapshot, WorldBinding)` for a genuinely new V8 account store and `openBound(file, WorldBinding)` for existing worlds. `WorldBinding` contains a native-supplied persisted world UUID and a **64-character lowercase SHA256 digest of the already-saved V8 graph/profile**. The sealed V2 image stores both, and rejects a mismatched world, changed saved profile, missing file, damaged frame, or unsupported format before it returns usable authority. A validly copied world-A image cannot be adopted through world-B's identity. Each CAS update preserves the exact original binding and checks binding and full-image fingerprint before acknowledgment. The helper deliberately **does not invent UUIDs or compute the native saved-profile hash**.

Historical `create/open` continue to support the earlier **unbound V1 checkpoint** for source/API compatibility, but `open` refuses V2 and `openBound` refuses V1. This is **not an automatic V1 adoption/migration**. A native owner must select the bound APIs, persist a stable world identity, canonicalize the saved V8 profile, and implement explicit save/edit/migration policy before any gameplay use. The decoder now also enforces strictly increasing signed keys for accounts, receivers, and replay receipts even if an attacker recomputes the outer SHA256; duplicate keys remain rejected. Valid earlier canonical V1 fixture frames remain unchanged.

The existing generation CAS, single-writer file lock, atomic replacement, forced file write, parent sync, replay receipt, and conserved water/salt/sediment transfer machinery are preserved. This class remains **explicit-call-only** and has no native finite-cell/world transaction linkage, renderer changes, or physical liquid-height changes.
