## Concrete reproduction and change

The baseline loads a real persisted page through the production worker and Vulkan upload. Entry pressure then closes its GPU meshes, but its disk key is gone (`indexed=false resident=0`); the new native assertion crashes. The exact-source control fails at the same lost-key condition. See [baseline failure](baseline-eviction-failure.json) and the preserved crash excerpt. The final fixture adds further controls after this first assertion; those later controls were not exercised by the original baseline.

The fix records whether a page was successfully written or read, uses an ordered unique index and requeues eligible evictions within the existing 8,192-key ceiling. Dirty or newer revisions, unwritten pages and disabled persistence cannot be admitted. Queued edit revisions survive dirty-entry displacement and reject stale reads before GPU publication. Self-review caught an intermediate implementation forgetting that guard; its exact-source failure and source remain separate.

Evicted pages wait until the player's chunk or memory setting changes, preventing a fixed-view disk/read/upload cycle. The player-chunk comparison is consistent even when the priority camera is displaced. Selection and disabled-index cleanup inspect at most 64 keys per call, up to two selection calls per scheduled tick. Ordered uniqueness and bounded metadata prevent duplicate index growth. This is scoped recovery, not a complete LOD hierarchy.
