## Source implementation

- Added `V8OceanConnectivity`, a bounded absolute-coordinate 32-block sampled wet-component lattice spanning signed 8192-cell regions. The v2 marine policy requires continuous sampled sea-depth paths from a query's four neighboring lattice points to a designated deep continental marine core. A region edge does **not** seed ocean. A dry/missing corner, unresolved connectivity or budget exhaustion **rejects** the marine claim rather than treating a lake as seawater. Work limits: 4 cached regions, 8 distinct regions/search, 96 components/search. Locks protect cache/BFS query order. No random or chunk-local state.
- `V8RoutedWaterSource.authorStitched(revision4)` explicitly creates a new routing **policy v2** fingerprint in a V8 *saved profile revision 5* envelope, requiring a saved continentalness graph field. `open()` selects legacy v1 or stitched v2 according to the pinned source fingerprint, rejecting mismatches. Frozen v1 fingerprint bytes and prior profiles are unchanged. This is a policy-version change within existing r5, **not** new r6 and **not** an automatic migration or native activation.
- The opt-in `sample()` marine classification now consumes stitched marine-core evidence while retaining the separately computed `WatershedRegion` sample for river/lake/bed geometry. This is **one correctness boundary**, not a global authoritative water-routing rewrite. In particular the priority-flood region planner is still locally edge-seeded, which may create wrong discharge/overflow or terminal outlets on real region boundaries. The sparse marine core is a heuristic; a deep inland depression can be mislabeled if its graph's continentalness indicates ocean, and 32-block sampling misses narrower passages.

No engine renderer source, V1–V7 geography, previous V8 profile snapshots, player edits, physical fluid amount or constituent accounting changed. No world chunks were modified. Existing v1 V8 routing still uses the old classification.
