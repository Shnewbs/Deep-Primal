# Strict technical review — Deep Primal alpha.28 / V7

**Overall: Tier 2 of 5 — Hobbyist Polished, with substantial prototype areas. Score: 50/100.** This is an engineering alpha below Indie Release-Ready. The label is the nearest tier in the supplied scale, not a claim that all visuals are polished. Functional and test infrastructure is stronger than the completeness, performance and visual finish. Scores are equally weighted reviewer judgments, not percentages of tests passing.

## 2. Overall tier and justification

Tier 2 is supported by a functioning custom generator, coupled regional drainage, finite-water accounting, versioned saves, modular boundaries and extensive reproducible checks. Tier 3 is blocked by incomplete worldgen features, unmet performance target, missing blending/structure architecture, visual/lifecycle issues and incomplete platform/long-duration validation. A successful build and millions of mathematical comparisons do not substitute for consistently good worlds or predictable gameplay costs. Tier 4/5 would require a much broader production toolchain, content/quality coverage and measured performance program.

## 3. Top five strengths

1. **Saved-world protection is real.** Frozen revisions, saved profiles, player-edit reload and legacy digest comparisons have actual native evidence.
2. **Drainage is connected and basin-aware.** Flow routing, accumulation, ocean classification and lake grouping exist as systems rather than unrelated river noise.
3. **Water accounting has explicit bounds and conservation checks.** Actual volumes, salt/sediment transfers and finite environmental stores are modeled. Current `WaterRuntime` retains pressure frontiers in 128-node turns, up to 8,192 nodes/job; it is not merely a permanently restarted 128-node search.
4. **Module separation is enforced.** The core does not depend on Minecraft/NeoForge/LWJGL, and build checks reject prohibited module coupling.
5. **Testing tracks actual bytes and failures.** Independently compiled classes, selected-package loaded identities, retained rejected runs and normal save/shutdown gates make the evidence stronger than a compile-only project.

## 4. Top ten weaknesses, ranked by impact

| Rank | Weakness | Concrete impact |
| ---: | --- | --- |
| 1 | Chunk generation misses budget and has no internal async handoff | Warm fills already cost about 3× the 5 ms target before lighting/IO; region setup reaches 224–266 ms in these runs. Shared region construction locks can stall competing generation work. Normal host scheduler traces are still required. |
| 2 | General 3D terrain composition is absent | Heightfield-based shape limits overhangs/floating formations and makes the requested unified continentalness/erosion/ridge/canyon density design unavailable to authors. Special river tunnels do not fill that gap. |
| 3 | Biome/ecotone transitions are threshold-driven | Abrupt surface/vegetation changes can remain even when the heightfield and vanilla tint interpolation are smooth. |
| 4 | Structure placement pipeline is absent | No built spacing/exclusion, world-space ownership, cross-chunk clipping or data-driven structure roster. Trees and ore veins are not a substitute. |
| 5 | Hydrology has bounded regional/temporal acceptance | Current pressure residency is 8,192 nodes/job with 16 jobs, and broad storm/drought/unloaded-border behavior is still open. Finite accounts do not by themselves ensure all natural streams look stable or remain balanced. |
| 6 | Cave morphology is narrow | Interpolated slice tubes/chambers with host gates do not establish distinct cheese/spaghetti/noodle systems, robust connections, readable entrances or comprehensive aquifer barriers. |
| 7 | Visual and lifecycle defects remain | Water flecks/flicker, mixed transparency, enabled-view distant coverage and recovery behavior prevent reliable finished presentation. Static test views do not establish temporal quality. |
| 8 | Data-driven extension surface is incomplete | Deposits/options are configurable; most world shape, climate palette logic, feature order and error localization remain hard-coded. No stable mod-facing worldgen stage API is delivered. |

## 5. Prioritized engineer fix list

1. **Make latency a gate, not a slogan.** Retain the new native fixture; add actual host status/thread traces, cold-region travel and parallel generators. Profile block/heightmap/ore work, remove demonstrably duplicated work with native output oracles, and measure p50/p95/p99/allocation before and after. Do not hold a global monitor through region computation. Use bounded deduplicated region jobs and cancellation/world ownership.
2. **Finish the V8 density stage.** Compile bounded JSON graphs to immutable field programs; layer continentalness, erosion, peaks/valleys and ridges, then domain warp and explicit 3D modifiers. Prove block/base-column consistency, feature bounds and signed chunk seams before registering V8. Keep V1–V7 class behavior frozen.
3. **Introduce weighted climate/ecotone rules.** Separate categorical biome IDs from blended material/vegetation weights. Add transition transects, neighboring chunk/order tests, palette validation and native side-by-side captures.
4. **Couple drainage and underground density.** Carve planned river stages into the density field; test lake outlets, mouth/bank heights, endoreic basins and deterministic domain boundaries. Add independent cheese/spaghetti/noodle masks, roof/fluid barriers and finite aquifer tests.
5. **Build feature ownership and spacing.** Implement deterministic candidates, exclusion radii, support predicates and stable ordering. Clip shared structures/vegetation into each owner chunk without neighbor writes. Add independent overlap/spacing and reversed-order native tests.
6. **Exercise live hydrology and presentation.** Run conserved loaded/unloaded/edit/save/reopen storm/drought cases, large components beyond current residency limits and matched moving-water captures. Fix exposed failures with measurements; do not add unlimited refill or freeze water as a visual workaround.
7. **Complete the authoring/API contract.** Snapshot versioned graph/biome/feature/deposit profiles into saves. Validate references, graph budgets and all numeric ranges with useful paths. Add example datapacks and compatibility/version rules for third-party stages.
8. **Port and validate the 26.3 adapter.** Audit worldgen registry/codec changes and the large graphics/GUI API migration. Compile and run native creation/reload/client/shutdown on the actual target before claiming support. Preserve the working 26.1.2 distribution.
9. **Broaden determinism and soak coverage.** Replay fixed world/chunk hashes on Linux/Windows and x86_64/ARM; cover generation order, cache eviction, simultaneous seeds, invalid configs and server restarts. Fix only in a new geographic revision if numeric behavior changes.
10. **Establish visual/content/performance sign-off.** A fixed multi-seed scene corpus, long gameplay sessions, supported hardware profiles including the owner's 8060S, automated result retention and explicit release blockers. Publish true whole-chunk/load-ready/frame/tick distributions.

The first noise/core stage is implemented in this checkpoint; the remaining fixes are open tasks. The architecture document orders implementation into noise, shape, biomes, hydrology, features and optimization; priority 1 defines measurements and constraints throughout, not permission to skip correctness stages.

## 6. What reaches Tier 3: Indie Release-Ready

Require a coherent, bounded supported feature set with no advertised missing systems; then prove it through a playable latest-target build. For this requested scope that includes integrated V8 density, blended surfaces/vegetation, routed rivers/basins/aquifers and the requested cave families, deterministic structures/features, complete validated saved profiles, stable extension hooks and ordinary gameplay/save compatibility.

Performance must meet a published hardware/workload budget with native stage and total load-to-ready distributions. For the owner's requested 5 ms average, show repeated representative measurements including cold amortization, and document tail limits and exclusions. Eliminate release-blocking water/LOD/transparency/lifecycle defects. Add cross-platform seed replay, sustained server/travel/save/load coverage, a useful setup/config/extension guide and reproducible release packaging.

Tier 3 does not require a large studio or marketing polish; it requires a reliable, supportable release with an honest scope. The current build has not passed that gate. Stages 2–6, owner-hardware validation and 26.3 support remain unimplemented or unaccepted.
